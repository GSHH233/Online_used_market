# 个人毕业设计选题说明

## 一、毕业设计题目

**基于 RAG 的二手商品智能发布与交易平台设计与实现**

## 二、选题背景

二手交易平台中的商品信息通常由用户自行填写，容易出现描述不完整、成色表述模糊、风险信息遗漏以及用户不了解平台规则等问题。同时，传统关键词搜索难以准确理解用户的口语化问题，平台规则文档也不便于普通用户直接查阅。

本课题拟设计并实现一个面向二手商品交易场景的 Web 平台。在完成商品浏览、发布、收藏和订单管理等基础功能的同时，引入检索增强生成（RAG）与大语言模型，为用户提供商品文案优化、发布风险提示和平台规则问答能力，提高商品信息完整性和规则查询效率。

## 三、系统建设目标

1. 实现二手商品从发布、浏览、收藏到订单状态流转的基础业务流程。
2. 实现 AI 发布助手，对商品标题、描述和发布风险进行辅助分析。
3. 建设平台规则知识库，为用户提供带参考依据的智能问答服务。
4. 实现知识文档上传、切分、索引和检索，支持后台人员维护知识内容。
5. 通过权限控制、检索评测和数据一致性检查，提高系统的安全性与可维护性。

## 四、功能模块

### 1. 用户账户模块

1. **用户注册**：用户填写用户名、密码、昵称和手机号完成账号注册。
2. **账号登录**：支持使用用户名和密码登录系统，并保持用户登录状态。
3. **验证码登录**：支持手机号验证码登录；当前演示环境由系统生成验证码并暂存，后续可接入第三方短信服务。
4. **身份区分**：区分普通用户、内部人员和管理员，为不同身份展示对应的功能页面。

### 2. 买家商品浏览模块

1. **商品列表**：分页展示在售商品的图片、标题、价格和成色。
2. **商品搜索**：买家可以根据商品名称关键词查找商品。
3. **条件筛选**：支持按照分类、价格范围和排序方式筛选商品。
4. **详情查看**：买家可以查看商品描述、价格、成色、所在地和卖家等详细信息。

### 3. 卖家商品发布模块

1. **商品信息填写**：卖家填写标题、描述、售价、原价、成色、分类和所在地等信息。
2. **商品图片上传**：卖家可以上传和移除商品图片，并在发布前查看封面预览。
3. **商品提交发布**：系统校验必填内容后保存商品，使商品进入平台的在售列表。
4. **发布结果查看**：商品发布成功后跳转至详情页，卖家可以核对最终展示内容。

### 4. 收藏与订单模块

1. **收藏管理**：用户可以收藏商品、取消收藏并分页查看个人收藏列表。
2. **创建订单**：用户在商品详情页发起购买，系统生成对应订单。
3. **订单查询**：用户可以查看订单列表及订单详情。
4. **订单状态流转**：支持模拟支付、取消订单、卖家发货和买家确认完成等操作，不涉及真实资金结算。

### 5. AI 商品发布助手模块

1. **信息完整性检查**：检查商品标题、描述、成色和价格等信息是否填写完整。
2. **文案优化**：生成优化后的商品标题和描述，由用户选择是否采用，不直接覆盖原内容。
3. **风险提醒**：提醒卖家注意夸大描述、凭证缺失和重要信息遗漏等问题。
4. **发布建议**：给出价格说明、风险等级和是否建议发布等结果。
5. **建议采用**：卖家可以一键采用优化后的标题或描述，再提交商品。

### 6. 平台规则问答模块

1. **规则问题咨询**：用户可以询问商品发布、交易安全和平台规则等问题。
2. **常见问题选择**：页面提供常见问题示例，用户可以直接选择并发起咨询。
3. **实时回答**：系统逐步展示回答内容，避免长时间等待时页面没有反馈。
4. **参考规则查看**：回答完成后展示相关规则名称和内容摘要。
5. **无法回答提示**：当系统没有找到足够依据时，提示用户补充信息或转人工确认。

### 7. 后台知识维护模块

1. **规则文档上传**：内部人员可以上传 Markdown、PDF、DOC 和 DOCX 格式的平台规则文档。
2. **文档列表查看**：按照关键词、文档状态和来源类型查询已经上传的知识文档。
3. **文档入库处理**：系统自动处理文档内容，并将其加入可检索的规则知识库。
4. **任务进度查看**：内部人员可以查看文档处理状态、完成结果和失败原因。
5. **知识检索验证**：输入测试问题，检查新上传的规则是否可以被正常查找到。

## 五、拟解决的五个关键技术问题

### 1. 如何实现用户登录和不同身份的权限控制

系统需要完成用户注册、密码登录和验证码登录，并安全保存用户密码。用户登录后，系统需要识别普通用户、内部人员和管理员身份，防止普通用户访问后台知识维护等内部功能。

### 2. 如何实现卖家商品发布和图片存储

卖家发布商品时需要填写标题、描述、价格、成色和分类等信息。系统需要校验必填字段和数据范围，将商品图片上传至对象存储，并把图片地址与商品信息正确关联后保存到数据库。

### 3. 如何实现买家商品搜索和分页展示

平台商品数量增加后，不能一次加载全部数据。系统需要支持按照关键词、分类和价格范围组合查询，并实现分页和排序，使买家能够快速找到商品，同时保证商品列表与详情数据一致。

### 4. 如何保证收藏和订单状态正确流转

系统需要避免同一用户重复收藏同一商品，并保证用户只能操作自己的收藏和订单。订单需要按照创建、支付、发货、完成或取消的顺序变化，同时限制买家和卖家只能执行各自允许的操作。

### 5. 如何将 AI 辅助功能接入商品发布和规则问答

系统需要把用户填写的商品信息传递给 AI 发布助手，并将文案建议和风险提示返回页面供用户选择。规则问答需要展示回答和参考依据；当 AI 服务异常或没有找到相关规则时，系统应给出明确提示，不能影响用户继续使用基础交易功能。

## 六、主要技术方案

- 前端：Vue 3、TypeScript、Pinia、Vue Router、Axios。
- 后端：Spring Boot、Spring AI、Spring Security、MyBatis-Plus。
- 数据与中间件：MySQL、Redis、Elasticsearch、Milvus、MinIO、RabbitMQ。
- 通信方式：RESTful API、WebSocket。
- AI 核心：文档切分、Embedding、Hybrid Retrieval、RRF、RAG 生成与拒答控制。

## 七、预期成果与演示流程

预期完成一个可以独立运行的二手商品交易与智能问答系统，并形成数据库脚本、接口文档、测试数据及核心功能测试报告。

建议答辩时按照以下顺序演示：

1. 注册或登录系统，进入商品市场。
2. 搜索商品、查看商品详情并添加收藏。
3. 填写商品信息，调用 AI 发布助手检查风险并采用文案建议。
4. 发布商品并创建订单，展示订单状态变化。
5. 在规则问答页面提出发布风险问题，展示流式回答和引用依据。
6. 使用内部账号上传一份规则文档，查看入库任务并执行知识检索。

## 八、课题范围说明

本课题的核心展示范围为二手交易基础业务、AI 发布助手、RAG 规则问答和知识库管理。项目中已有的智能运维、多 Agent 编排和运行时恢复能力可作为扩展成果介绍，但不作为毕业设计现场演示的必要前置条件。支付和短信功能采用演示实现，不接入真实资金结算；正式部署时可进一步对接支付平台及第三方短信服务。
